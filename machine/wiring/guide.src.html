Before you start

  • Tools: small flat screwdriver, wire stripper, multimeter with a continuity beeper, ferrule crimper, soldering iron (step 5 only).
  • Wire: 18 AWG red and black for power, 22 AWG for signals. Ferrules to suit both.
  • Two Wago 221-415 lever nuts. One is the +24 V bus, one is the GND bus.
  • Three JST-XH 2.54 mm 3-pin plugs (or a crimp kit) for the endstop cables. The limit inputs are sockets, not screw terminals.
  • A barrel-jack-to-screw adapter rated 10 A that matches the brick's tip. Many are rated 3–5 A. Or cut the brick's plug off and put its leads straight into the lever nuts.

Four rules

  1. The power brick stays unplugged from the wall while you wire.
  2. Never plug or unplug a motor while the power is on. It destroys the driver.
  3. Red is always +, black is always GND. Check with the meter before the first power-up.
  4. The brick is set to 24.0 V and never higher. The board's main input is rated 9–24 V.

Reading the drawings

An orange dashed box marks the terminals you touch in that step. The PiBot drawing is simplified, but every connector is on the correct edge of the board. Several of the board's terminals have no pin labels. Where that matters, the step says how to find each pin with the meter.

A

Board setup: jumpers

Set the PiBot's jumpers for this machine before anything is connected. The circled numbers match PiBot's V4.96 Pro pin definition overview, so you can find each one on their board photo.

Do first

  1. Board unpowered, USB unplugged, nothing on any terminal.
  2. Screw on the Wi-Fi antenna. Without it there is no Wi-Fi. Plug in the OLED. A TF card is optional.
  3. Use tweezers or pliers for the jumpers (the small plastic caps that bridge two pins). Fit or remove each one, then check it against the table again.
  4. Most jumper headers here have 3 pins: the jumper joins the middle pin to one side, so the side matters. The table says which.

Careful

  1. Each of the six driver slots has a StepStick socket: two rows of 8 female header pins that a plug-in driver board pushes into. Your TMC2209s are StepSticks, and they go in the sockets of slots 2 and 3.
  2. Slot 1 (X on the silkscreen) is different. The DM542T is an external driver and doesn't plug in. Fit all four of slot 1's routing jumpers (header H4, beside the socket), and leave slot 1's socket empty.
  3. Never put a TMC2209 in slot 1. With the routing jumpers in, its 24 V motor outputs land on the board's logic lines. That destroys the driver and the board's chips.
  4. The board ships with only three jumpers fitted (VDD, SW-VCC, RLY). Every other jumper in this table is one you add.

Check before moving on

  1. Count the jumpers: 9 on the board in total, whatever the board shipped with. VDD on +5V (1), SW-VCC on +5V (1), RLY on relay (1), slot 1 routing (4), MS1 and MS2 on the same side as RLY (2). Nothing on USB-5V, NULL, RST, SLP, SPI or slots 2–6.
  2. If your count isn't 9, compare each row of the table above with the board until it is. Spare jumpers go in a bag, not on unused pins.
  3. Optional meter check once the board has 24 V (section B): socket 2's MS1 and MS2 pins read about 5 V to GND. The bench test in section C proves this anyway.
B

Firmware and config

The board ships with FluidNC 3.9.9 already flashed and a factory test config. You don't need to flash anything. You only upload our two config files.

Power the bare board

  1. The power inputs are the orange connectors on the board's bottom edge, labelled underneath: Vmot-Driver, Vmot, then MOSFET and RELAY.
  2. Wire only the first two pairs of step 1: brick → lever nuts → Vmot (+ and − are printed under it). Vmot is a plug: pull it straight off, wire it, push it back on. Nothing else connected yet.
  3. Plug in the brick. The 5 V LED lights and the OLED shows FluidNC.
  4. Meter across Vmot-Driver: about 0 V. It's a separate input that only feeds the driver sockets.

Not a power input

  1. The black 5-pin header near the ESP32 is labelled GP27, GP25, +5V, VMOT Main, GND. It's an output for add-on modules. Never connect the brick there.

Open the web interface

  1. On a laptop or phone, join Wi-Fi FluidNC, password 12345678.
  2. Browse to http://192.168.0.1. That opens FluidNC's WebUI.
  3. Optional: PiBot's own 60-minute factory checklist tests every input and output with the factory config. Run it now if you want a known-good board before you start.

Upload our configs

  1. From the repo, copy machine/fluidnc-bench.yaml as bench.yaml and machine/fluidnc-config.yaml as stringart.yaml.
  2. Upload both to the board's flash, not the SD card: FluidNC only reads its config from flash. The Files panel on the WebUI dashboard shows only the SD card. The flash is under the FluidNC tab at the top of the WebUI: press Manage local files and upload there. Leave the factory config.yaml there as a fallback.
  3. In the WebUI console, send these one line at a time:
$Config/Filename=bench.yaml
$Bye                       (restarts the board)
$SS                        (startup log: look for errors)
$CD                        (prints the config it actually loaded)

The startup log should have no [MSG:ERR: lines. $CD should show name: StringArtBench. A config problem leaves the board in alarm, and $X then answers "Configuration is invalid". To go back to the factory test config, send $Config/Filename=config.yaml and $Bye.

Only if you ever need to re-flash

  1. Use Chrome or Edge, which can open serial ports from a web page. Go to installer.fluidnc.com, plug in USB and pick the port.
  2. Choose Install FluidNC, then pick release v3.9.9 to match the factory firmware (the newest 4.x also accepts our configs). Then processor esp32 if asked, firmware variant wifi, installation type fresh-install. In the confirm box, under Extra Options, tick Install WebUI-2, then Install.
  3. If it reports "Bootloader not active", hold the board's BOOT button while it connects.
  4. Linux: the board's CP2102 USB chip needs no driver, but your user must be in the dialout group (uucp on Arch): sudo usermod -aG dialout $USER, then log out and back in.
  5. A fresh install wipes the flash, so upload both YAML files again afterwards.
C

Bench test: one motor

Before the full wiring, prove one driver, one motor and the config on the bench. Each test command turns the motor shaft exactly once, so it checks the microstep setting as well as the wiring. Uses bench.yaml, which has no homing, so you can jog straight away.

Test 0: signal LEDs, no motor

  1. Power goes only to the orange Vmot connector on the right edge of the board (CN3). Leave the Vmot-Driver screw terminal unconnected, the driver sockets empty and every motor unplugged.
  2. Check that the board is running bench.yaml: send $SS. The log should show Configuration file:bench.yaml and no [MSG:ERR: line. If it names a different file, send $Config/Filename=bench.yaml, then $Bye.
  3. Find the signal LEDs: each slot has a column of three small LEDs just right of its socket, labelled by the I2S output that drives them, not by name. Slot 1: I2.0 = EN, I2.2 = STEP, I2.1 = DIR. Slot 2: I2.7 = EN, I2.5 = STEP, I2.4 = DIR. Slot 3: I2.8 = EN, I2.10 = STEP, I2.9 = DIR.
  4. The EN LEDs (I2.0, I2.7, I2.8) should be off. A lit EN LED means that driver is switched off; off means the config is holding it on.
  5. Send $J=G91 X10 F300, then $J=G91 X-10 F300. Slot 1's DIR LED (I2.1) changes state between the two: on for one direction, off for the other. The STEP LED (I2.2) may glow faintly or not visibly at all: the pulses are only 4 µs long. The DIR LED is the reliable check.
  6. Repeat with $J=G91 Y10 F600 and $J=G91 Y-10 F600: slot 2's DIR LED (I2.4) changes state. This is PiBot's test 2.8.

Test 1: threader pancake on a TMC2209

  1. Brick unplugged. Add step 1's Vmot-Driver pair. TMC2209 in socket 2, EN pin to the EN mark.
  2. Power on and set Vref to 0.9–1.0 V (step 3). It reads 0 V until Vmot-Driver has 24 V.
  3. Brick unplugged again. Meter the pancake's coils and connect it to slot 2's terminal as in step 3: black and blue on the two screws at one end, green and red on the two at the other. Stick a tape flag on the shaft.
  4. Power on. Send $J=G91 Y40 F600: the shaft turns exactly once in 4 s. Send $J=G91 Y-40 F600: it turns back.

Test 2: platter NEMA23 on the DM542T

  1. Brick unplugged. Wire step 1's DM542T pair and all of step 2, with the DIP switches set and the DM542T's 5V/24V selector (if it has one) on 5V.
  2. Power on. The DM542T's green LED lights, and the red one stays off.
  3. Send $J=G91 X72 F600: the NEMA23 shaft turns exactly once in about 7.5 s. (72 nails × 44.444 = 3200 steps.) $J=G91 X-72 F600 brings it back.
  4. With the belt and platter fitted, upload and run machine/platter-test.gcode (about 6 min). It runs half turns at rising speeds, full-speed turns and a threading pattern, and stops for 5 s after each part so you can check that a mark on the rim still lines up with a fixed pointer. If it drifts or sounds rough, lower max_rate_mm_per_min or acceleration_mm_per_sec2 on X.

When both motors pass

  1. Power off and finish wiring with steps 1–5 below.
  2. Then switch to the real config: $Config/Filename=stringart.yaml and $Bye. It expects homing, so it starts locked. $H homes once the endstops are in. $X unlocks without homing, but then nail 0 is wherever the platter happens to be.
✓

First full power-up

Everything is wired. Go through this once before plugging the brick into the wall.

Checklist

  1. Every motor is plugged in, and stays plugged in while the power is on.
  2. No loose copper strands at any screw terminal. Tug every wire.
  3. Meter: 24 V on the lever nuts, not more.
  4. Jumpers still match section A (9 in total). Slot 1's socket is empty.
  5. Both TMC2209s point the right way, Vref set to 0.9–1.0 V.
  6. $Config/Filename=stringart.yaml, $Bye, then $SS shows no [MSG:ERR: lines.
  7. Send ?. There is no Pn: entry with every switch at rest.
  8. Home with $H: Y and Z home first, then X finds nail 0. Keep a hand on the wall plug the first time.
  9. Drill test with the bit out: M3 S1000 spins it after the 2 s spin-up wait, M5 stops it. If the board resets when the drill starts, see step 5.
