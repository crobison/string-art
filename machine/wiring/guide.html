Before you start

  • Tools: small flat screwdriver, wire stripper, multimeter, ferrule crimper, soldering iron (step 5 only).
  • Wire: 18 AWG red and black for power, 22 AWG for signals.
  • Two Wago 221-415 lever nuts. One is the +24 V bus, one is the GND bus.

Three rules

  1. The power brick stays unplugged from the wall while you wire.
  2. Never plug or unplug a motor while the power is on. It destroys the driver.
  3. Red is always +, black is always GND. Check with the meter before the first power-up.

Reading the drawings

An orange dashed box marks the terminals you touch in that step. Header positions on the PiBot drawing are simplified. On the real board, always match the labels printed next to the pins.

A

Board setup: jumpers

Set the PiBot's jumpers for this machine before anything is connected. The circled numbers match PiBot's V4.96 Pro pin definition overview, so you can find each one on their board photo.

Do first

  1. Board unpowered, USB unplugged, nothing on any terminal.
  2. Screw on the Wi-Fi antenna. Without it there is no Wi-Fi. Plug in the OLED. A TF card is optional.
  3. Use tweezers or pliers for the caps. Fit or remove each one, then check it against the table again.

Careful

  1. Slot 1 gets routing jumpers for the DM542T, so slot 1's StepStick socket must stay empty. A driver in a jumpered slot destroys the driver and the board's chips.
  2. The board ships with only three caps fitted (VDD, SW-VCC, GPIO26). Every other cap in this table is one you add.

Check before moving on

  1. Count the caps: USB-5V off; VDD on 5V; SW-VCC on 5V; GPIO26 on Relay; slot 1 routing caps in; MS1 and MS2 in; nothing else.
  2. Optional meter check once the board has 24 V (section B): socket 2's MS1 and MS2 pins read about 5 V to GND. The bench test in section C proves this anyway.
B

Firmware and config

The board ships with FluidNC 3.9.9 already flashed and a factory test config. You don't need to flash anything. You only upload our two config files.

Power the bare board

  1. Wire only the first two pairs of step 1: brick → lever nuts → Vmot-main. Nothing else connected yet.
  2. Plug in the brick. The 5 V LED lights and the OLED shows FluidNC.

Open the web interface

  1. On a laptop or phone, join Wi-Fi fluidnc, password 12345678.
  2. Browse to http://192.168.0.1. That opens FluidNC's WebUI.
  3. Optional: PiBot's own 60-minute factory checklist tests every input and output with the factory config. Run it now if you want a known-good board before you start.

Upload our configs

  1. From the repo, copy machine/fluidnc-bench.yaml as bench.yaml and machine/fluidnc-config.yaml as stringart.yaml.
  2. In the WebUI, open the file browser for the board's flash (not the SD card) and upload both. Leave the factory config.yaml there as a fallback.
  3. In the WebUI console, send these one line at a time:
$Config/Filename=bench.yaml
$Bye                       (restarts the board)
$SS                        (startup log: look for errors)
$CD                        (prints the config it actually loaded)

The startup log should end without any error or Bad config lines. $CD should show name: StringArtBench. To go back to the factory test config, send $Config/Filename=config.yaml and $Bye.

Only if you ever need to re-flash

  1. Use Chrome or Edge, which can open serial ports from a web page. Go to installer.fluidnc.com, plug in USB and pick the port.
  2. Choose Install → WiFi build → Fresh install → WebUI 2, then wait for 100%. If it gets stuck in a boot loop, hold the BOOT button for 3 s and release.
  3. Linux: the board's CP210x USB chip needs no driver, but your user must be in the dialout group: sudo usermod -aG dialout $USER, then log out and back in.
  4. A fresh install wipes the flash, so upload both YAML files again afterwards.
C

Bench test: one motor

Before the full wiring, prove one driver, one motor and the config on the bench. Each test command turns the motor shaft exactly once, so it checks the microstep setting as well as the wiring. Uses bench.yaml, which has no homing, so you can jog straight away.

Test 0: signal LEDs, no motor

  1. Board on Vmot-main only, bench.yaml active. Each slot's EN LED is lit.
  2. Send $J=G91 X10 F300, then $J=G91 Y10 F600. Slot 1's and then slot 2's CLK and DIR LEDs flicker while the axis "moves". This is PiBot's test 2.8.

Test 1: threader pancake on a TMC2209

  1. Brick unplugged. Add step 1's Vmot-driver pair. TMC2209 in socket 2, EN pin to the EN mark, Vref set to 0.9–1.0 V (step 3).
  2. Brick unplugged again. Connect the pancake to slot 2's terminal: black 1A, green 1B, red 2A, blue 2B. Stick a tape flag on the shaft.
  3. Power on. Send $J=G91 Y40 F600: the shaft turns exactly once in 4 s. Send $J=G91 Y-40 F600: it turns back.

Test 2: platter NEMA23 on the DM542T

  1. Brick unplugged. Wire step 1's DM542T pair and all of step 2, with the DIP switches set.
  2. Power on. The DM542T's green LED lights, and the red one stays off.
  3. Send $J=G91 X72 F600: the NEMA23 shaft turns exactly once in about 7 s. (72 nails × 44.444 = 3200 steps.) $J=G91 X-72 F600 brings it back.

When both motors pass

  1. Power off and finish wiring with steps 1–5 below.
  2. Then switch to the real config: $Config/Filename=stringart.yaml and $Bye. It requires homing, so it won't jog until the endstops are in and $H has run.
✓

First full power-up

Everything is wired. Go through this once before plugging the brick into the wall.

Checklist

  1. Every motor is plugged in, and stays plugged in while the power is on.
  2. No loose copper strands at any screw terminal. Tug every wire.
  3. Meter: 24 V on the lever nuts.
  4. Jumpers still match section A. Slot 1's socket is empty.
  5. Both TMC2209s point the right way, Vref set to 0.9–1.0 V.
  6. $Config/Filename=stringart.yaml, $Bye, then $SS shows no errors.
  7. Send ?. There is no Pn: entry with every switch at rest.
  8. Home with $H: Y and Z home first, then X finds nail 0. Keep a hand on the wall plug the first time.
  9. Drill test with the bit out: M3 S1000 spins it, M5 stops it.
